# Leave the clipboard alone

Typelite used the clipboard in ways users notice: a result it could not type was copied over
what they had copied, a paste put back only plain text (an image or a file was lost), and reading
a highlight put a placeholder string on the clipboard and could leave an app's late copy there.
This plan makes the clipboard change only when the user asks, and come back whole when Typelite
borrows it.

Status: done - 2026-10-17.

## Goals and non-goals

- The clipboard holds what the user put there, unless they press Copy in Typelite.
- When Typelite borrows the clipboard to paste, everything comes back: every item and type
  (formatted text, images, files), not only plain text.
- Reading a highlight does not touch the clipboard when the app can say what is selected.
- Clipboard managers do not record Typelite's temporary text.
- Not a goal: a different typing method. Keyboard output never used the clipboard and is
  unchanged.

## Key decisions

| Decision | Reason |
|---|---|
| A Dictate or Translate result that cannot be typed into the app the user started in waits in the Copy pill: another app is in front, Typelite has no Accessibility permission, or no text field has focus | It used to be copied to the clipboard on its own, over the user's copy. The Copy pill already exists for "no text field" (plan `copy-when-no-field`). Supersedes that plan's "a changed target app keeps its copy-to-clipboard fallback". |
| A user's "copy-only" insertion setting still copies | They chose the clipboard. |
| The app the recording started in is read at the shortcut, in-process (`NSWorkspace.frontmostApplication`), like the paste check | It came from a cache refreshed about once a second through AppleScript, so a shortcut pressed right after switching apps recorded the previous app and the paste check copied instead of typing. |
| Paste saves and restores the whole pasteboard (`output::pasteboard`), and restores only while the pasteboard's change count still matches Typelite's write | Plain text lost images, files and formatting; the change count tells reliably whether anything was copied since, without comparing contents. |
| Temporary text carries `org.nspasteboard.TransientType` and `org.nspasteboard.AutoGeneratedType` | The nspasteboard.org convention that clipboard managers honour, so dictations do not fill their history. |
| A highlight is read through Accessibility (`AXSelectedText`) first; ⌘C only when the app does not tell | No clipboard at all for most apps, including "nothing selected". |
| The ⌘C fallback watches the change count instead of writing a placeholder, puts the whole clipboard back, and for 1.5 s puts it back again if the app copies late | The placeholder (`__typelite_copy_sentinel_…`) could be pasted or recorded, and an app that answered after the 500 ms wait left the selection on the clipboard. |

## Parts

None; the decisions above are the plan. Code: `output/pasteboard.rs`, `output/clipboard.rs`,
`selection.rs`, `output/focus.rs` (`focused_selected_text`), `copy_pill.rs`
(`copy_pill_hold`), `app_detector/cache.rs` (`snapshot_for_recording_enabled`).

## Open questions

- Outside macOS the clipboard snapshot is still plain text only (Windows and Linux are not
  targets).
- A user who copies something within 1.5 s of an Ask whose ⌘C copied nothing in time gets their
  older clipboard back. Rare, and preferable to the selection being left there.
